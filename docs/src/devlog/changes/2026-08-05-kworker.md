# ANE-CHG-20260805-kworker

**Type:** Small feature / contract-bearing local cutover
**Status:** Completed
**Date:** 2026-08-05
**Authors:** doruche, Codex
**Area:** task / kworker / kthread / scheduler wake / timer / irq

## Problem / Context

threaded timer原先为每个CPU维护独立的ready queue、worker slot、kthread、wake/drain loop与yield protocol。继续让
短小的process-context异步owner复制这套形状，会重复queue ownership、wait/wake、lifecycle与progress规则，也会为
稀疏后台任务增加常驻kthread。

本轮需要一个最小共享执行底座，但不需要Linux CMWQ parity：固定boot topology、匿名one-shot closure、同queue FIFO、
hard IRQ enqueue与普通kthread execution context足以支撑首个真实consumer。需要长期阻塞、独立lifecycle、owner service
loop或队头阻塞隔离的consumer继续直接使用`task::kthread`。

## Decision

`task::kworker`在所有CPU online后、unordered `Late` initcall前由BSP一次性创建每CPU一个system worker，并seal
topology。每个worker拥有自己的`VecDeque<Box<dyn FnOnce() + Send + 'static>>`；`SystemWorker::submit(F)`在
`push_back`处转移closure ownership，unlock后发布pure wake，worker逐项pop、调用并yield。submission不返回handle或
admission result，不提供physical cancellation、completion、flush、drain、join、resize、hotplug或backpressure。

hard IRQ producer只做noirq queue push和unlock后的既有wake；当前工程阶段接受Box/VecDeque及wake transport可能产生的
heap allocation，OOM按kernel fatal policy处理。callback必须短小、有界，执行于interrupts enabled、允许抢占的process
context；长任务、blocking work或需要独立lifecycle的owner仍使用owner-local kthread。

threaded timer继续唯一拥有deadline、expiry与cancellation；到期callback转交当前CPU的system worker。timer私有queue、
worker slot、entry、late initcall和drain/wake loop全部删除，timer callback的process-context与stale-validity语义保持。

## Implementation Boundary

`task::kworker`是activation、per-CPU topology、queue ownership与worker drain/progress owner；`task::kthread`拥有
cooperative lifecycle，scheduler拥有runnable/placement，timer拥有deadline/cancellation，具体consumer拥有callback
validity。受保护边界是无userspace ABI变化、每CPU单一sealed slot、同queue FIFO/at-most-once、IRQ unlock-before-wake、
process-context callback与timer deadline/cancellation不变。失败沿既有fatal policy；无runtime teardown或physical
cancellation cleanup protocol。

本轮不迁移OOM、inode shrinker、TTY、network pump或其它长期service thread，不引入dedicated registration/factory、
work handle、pending-bit/coalescing、固定容量/backpressure、scheduler policy或Linux CMWQ compatibility claim。

## Change

- 新增`task::kworker` sibling module：boot activation、per-CPU queue/slot、submission capability、predicate wait、
  pop-before-call与每项yield；增加topology、FIFO/at-most-once与self-submit owner-local KUnit。
- 在BSP all-CPU-online barrier之后、`run_initcalls(InitCallLevel::Late)`之前调用system-worker activation。
- 将threaded timer expiry改为提交本地system worker；删除timer私有ready queue、worker slot、worker entry/initcall、
  backlog统计与private drain/wake loop；增加timer process-context burst KUnit。
- 保持timerfd、itimer与network deadline调用timer API；不扩大其它consumer。

  `THREADED_WORKER`、timer worker entry/initcall及private drain/wake loop已删除。
- `just build --preset qemu-virt-rv64-release --bind smp=2 --bind memory=1G`在sandbox内先于lwext4 C编译触发既有
  `Bad system call`/SIGSYS；同一canonical命令在sandbox外完成discovery/final kernel build与symtab校验。
- `just qemu --preset qemu-virt-rv64-release --bind smp=2 --bind memory=1G --bind kernel-image=build/anemone.elf
  --bind disk-x0=build/runtime/pretest-rv64/disk-x0.img --bind disk-x1=build/rootfs/pretest-rv64/rootfs.img`显示
  `Platform HART Count : 2`，完成`435/435` KUnit；topology、FIFO、self-submit、timer process-context与burst测例均
  `ok`，随后user-test socket profile报告`attempted=6 passed=6 failed=0 infra_failed=0`并进入orderly PowerOff。
- source/concurrency audit确认`push_back`是ownership linearization point、queue unlock-before-wake、worker
  pop-before-call、callback/drop不在queue lock内，且无dedicated registration/factory、runtime worker mutation或
  work completion/cancel/flush API。
- source call-chain audit确认`ITIMER_REAL`的validness/interval rearm/signal commit、timerfd的generation/
  expiration accounting/waiter handoff，以及network pump的deadline/predicate truth仍由原consumer owner持有；三者均
  继续经`schedule_threaded_timer_event()`进入timer core，再由到期IRQ转交local system worker。
- `mdbook build docs`通过。独立subagent review确认boot ordering、submission ownership、unlock-before-wake、
  pop-before-call、per-item yield、timer owner边界与旧private timer worker残留均正确，未发现Apollyon、Keter或
  Euclid代码finding；其指出的三个focused consumer runtime证据缺口按下述`Not Run`保留。

## Remaining Risk / Links

- 无backpressure的shared queue可能在producer长期快于consumer时增长至OOM panic；这是当前fatal allocation policy的
  显式边界，不是resource guarantee。长时间或blocking callback会阻塞同worker后继，需独立lane时另行分类。
- hard IRQ submission仍允许heap allocation；[`ANE-20260622-IRQ-OFF-HEAP-ALLOCATION`](../../register/open-issues.md#ane-20260622-irq-off-heap-allocation)不因本轮关闭。
- **Not Run:** `ITIMER_REAL` expiry、timerfd expiry与network deadline的各自focused runtime；LA64 build/runtime、
  full LTP、physical hardware、final harness、CPU hotplug、OOM exhaustion、strict latency/fairness、allocation-free
  IRQ或Linux CMWQ compatibility。前三项的owner/call-chain由source audit证明，不把通用threaded-timer KUnit或socket
  profile误述为其运行证据。

- Runtime evidence：build-local `build/kworker-kunit-rv64-smp2.log`，不进入public source。
