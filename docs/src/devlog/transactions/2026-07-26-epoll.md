`usize::MAX = Retired`。最后一个 published ref 的 release CAS 是 terminal retirement
线性化点；后续 publication 命中常开 assertion，旧 identity 不再允许 `0 -> 1` revival。

**Capability shape:** `OpenedDescriptionCapability` 只保存 `Weak<ProcFile>`，identity 比较使用
`Weak::ptr_eq`；`Weak::upgrade()` 不作为 semantic liveness。不可 clone 的
`OpenedDescriptionLease` 只为一次 operation 强持 target storage，取得 lease 和 commit 前
validation 都读取同一个 lifecycle word；lease 不延迟或撤销 retirement。静态
`FileDescOps::final_release` hook 未修改，也未增加 dynamic observer 或 epoll-side alive bit。

**Publication/release audit:** first open 与 reservation commit 只允许
`Unpublished -> Live(1)`；dup/dup3/fork 在其 source table slot 仍受锁保护且 live 时增加 count；

replacement 与 exit drain 都先移除 published slot，再在锁外走同一 release CAS。跨 table
publication 时原 alias 仍贡献 live ref，因此 live count 不会正常到达 `Retired` 后再增加。
`FileDesc::Clone` 或未来 delayed publication 若违反该前提，会由 production assertion 暴露，
没有为 panic 增加 test hook。

**KUnit:** 保留一项 owner-local case，使用真实 `FilesState` open/dup/close owner 验证两个 alias
identity 相同、关闭一个后 capability 仍能取得 lease、最后一个 published ref 退休后旧
capability 无法取得 lease且既有 lease validation 失败。显式 RV64 build 启用了 `kunit`，因此

**Result:** Closed。按开发者要求把原 `fs/iomux.rs` 目录化为

**Consumer lifecycle:** `IomuxWaitRound` 线性拥有本轮 `Latch`、`LatchTrigger`、observer
acceptance 与 route origin。正常与 Drop fail-close 路径都先把唯一 callback-acceptance bit 从

concurrency review 发现临时强引用可能在 source lock 内成为最后 observer owner。最终实现改为只读
