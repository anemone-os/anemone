## Checkpoint log

### Checkpoint 0A - Opened-description Terminal Liveness - 2026-07-26

**Result:** Closed。`task::files` 继续以 `ProcFile::description_refs` 为唯一 lifecycle truth，
但把原子字明确编码为 `0 = Unpublished`、`1..=usize::MAX - 1 = Live(n)`、
`usize::MAX = Retired`。最后一个 published ref 的 release CAS 是 terminal retirement
线性化点；后续 publication 命中常开 assertion，旧 identity 不再允许 `0 -> 1` revival。

**Capability shape:** `OpenedDescriptionCapability` 只保存 `Weak<ProcFile>`，identity 比较使用
`Weak::ptr_eq`；`Weak::upgrade()` 不作为 semantic liveness。不可 clone 的
`OpenedDescriptionLease` 只为一次 operation 强持 target storage，取得 lease 和 commit 前
validation 都读取同一个 lifecycle word；lease 不延迟或撤销 retirement。静态
`FileDescOps::final_release` hook 未修改，也未增加 dynamic observer 或 epoll-side alive bit。

**Publication/release audit:** first open 与 reservation commit 只允许
`Unpublished -> Live(1)`；dup/dup3/fork 在其 source table slot 仍受锁保护且 live 时增加 count；
CLONE_FILES 共享同一 table，不重复 publication；unshare、single/range close、cloexec、table
replacement 与 exit drain 都先移除 published slot，再在锁外走同一 release CAS。跨 table
publication 时原 alias 仍贡献 live ref，因此 live count 不会正常到达 `Retired` 后再增加。
`FileDesc::Clone` 或未来 delayed publication 若违反该前提，会由 production assertion 暴露，
没有为 panic 增加 test hook。

**KUnit:** 保留一项 owner-local case，使用真实 `FilesState` open/dup/close owner 验证两个 alias
identity 相同、关闭一个后 capability 仍能取得 lease、最后一个 published ref 退休后旧
capability 无法取得 lease且既有 lease validation 失败。显式 RV64 build 启用了 `kunit`，因此
production 与 test body 已编译；按 Stage 0 计划，KUnit runtime 留待 0D closure wrapper，当前
明确 Not Run。

**Validation:** `just fmt kernel --check` PASS；`git diff --check` PASS；
`just build --preset qemu-virt-rv64-release --bind smp=1 --bind memory=1G` 首次在 sandbox 内的
lwext4 C compile 命中 host `SIGSYS`，相同命令在 sandbox 外复跑 PASS。task/files lifecycle
review 没有未关闭 finding，未触发 terminal-retirement、long-lived strong target、dynamic
final-release observer、owner/ABI/acceptance 或 write-set 停止条件。

**Contract / handoff:** contract cutover 仍为 `None`；0A slice 保留给 Stage 1 原子吸收。

### Checkpoint 0B - Observer Core、IomuxWaitRound 与 Pipe Slice - 2026-07-26

**Result:** Closed。按开发者要求把原 `fs/iomux.rs` 目录化为
`fs/iomux/{mod,subscription,wait}.rs`；这是同一 iomux owner 内的结构拆分，没有改变 public
ABI、shared contract 或依赖方向。`subscription` 的 private `PollObserver` 与 crate-internal
`PollRoute` 形成 source-neutral、non-owning route；source 只能 clone、判断 hygiene 和执行
no-return notify，不能取得 consumer、`Latch`、task 或 callback result。

**Consumer lifecycle:** `IomuxWaitRound` 线性拥有本轮 `Latch`、`LatchTrigger`、observer
acceptance 与 route origin。正常与 Drop fail-close 路径都先把唯一 callback-acceptance bit 从
live 置为 retired，再 finish latch；已在 retire 前读到 acceptance 的 callback 即使晚到，也只会
命中 `LatchTrigger` 的 stale wait identity。`PollRequest` 在 Stage 0 同时携带新 route 与旧 trigger
bridge；pipe 只消费 route，其余 source 继续消费 trigger，删除条件仍是 Stage 1
`SUBSCRIPTION-CUTOVER`。

**Pipe publication / resource bound:** pipe 的 RX/TX registry 使用 source-owned
`Arc<Vec<PipePollRoute>>` snapshot。subscribe 在 pipe lock 内用 `try_reserve` 与 `Arc::try_new`
完整构造 replacement，只有全部分配成功后才 publication，随后在同一临界区 snapshot current
readiness；因此 ready-at-subscribe 也保留 route，OOM 不暴露半 entry。顺序 round 在下一次
subscribe prune 已失效 route；保留量受当前并发 wait registrations 加最后一个 registry snapshot
约束，不依赖同步 unlink。read/write/endpoint-drop 在锁内只更新 predicate 并 clone registry
snapshot，锁外按 interest 发布 hint；旧 registry 的 drop 也在锁外，state transition 不分配。

**Final-scan / signal boundary:** ppoll/pselect 的 register-ready、unsupported 与 error 分支都先
retire observer acceptance、finish latch，再执行完整 snapshot scan；register payload 不再直接成为
返回 truth。temporary mask、delivery reservation、outcome classifier 与 restore/defer responsibility
仍全部位于既有 syscall/Signal owner，`IomuxWaitRound` 没有取得 `SIGNAL-TEMP-MASK-*` 状态。

**Source classification:** pipe 是本 checkpoint 唯一 `Subscribed(PollEvent)` source。
eventfd、fanotify、timerfd 与 TTY 仍使用 `LatchTrigger` / `Armed` bridge；regular/ext4/ramfs/proc
等 snapshot-only source 继续用 `Ready` / `Unsupported`。现有 TTY direct KUnit 仍通过 legacy
`PollRequest::register` 构造，不产生新 route caller。

**Review finding:** 初版 `PollRoute::is_prunable()` 曾通过 `Weak::upgrade()` 检查 retirement；
concurrency review 发现临时强引用可能在 source lock 内成为最后 observer owner。最终实现改为只读
`Weak::strong_count() == 0` 的保守 hygiene hint，不在 source lock 内取得或 drop consumer strong
reference；正确性继续只由 observer acceptance 与 stale latch identity 保证。修正后没有未关闭
Apollyon、Keter 或 Euclid finding。

**Validation:** `just fmt kernel --check` PASS；`git diff --check` PASS；
`mdbook build docs` PASS，且 implementation 指向本 checkpoint 的生成页 anchor 可解析；
`just build --preset qemu-virt-rv64-release --bind smp=1 --bind memory=1G` 在 sandbox 内仍于 lwext4
C compile 命中 host `SIGSYS`，sandbox 外相同命令最终 PASS，包含 `kunit` feature 编译。

`account_due_expiration_locked()` predicate transition 与 `notify_waiters_after_unlock()`：覆盖
ready-at-subscribe 先保存 route、notification 后 live route 仍留在 registry、retired route 在下一次
subscribe 中被 guard 内 detach 并于 guard 外 drop、固定容量 16 的可观察耗尽与容量回收，以及解锁后
