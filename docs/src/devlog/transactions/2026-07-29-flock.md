### 2026-07-29 - Checkpoint 0A implementation and review

新增 private `fs::flock` owner，并让每个 `Inode` 构造一份
`SpinLock<Vec<FlockGrant>> + Event` domain。grant collection 是 holder × inode mode/conflict 的唯一真相，entry
只保存 `OpenedDescriptionCapability + FlockMode`；没有 fd/path/pid key、waiter/candidate queue、backend hook、
mode mirror或公共 lock framework。normalized request在入口取得operation-local lease，每次commit在domain guard
下重验liveness与conflict；same-mode幂等，unlock只删除same owner，conversion先删除old mode并在guard外drop/
broadcast，再独立竞争target mode，后续nonblocking conflict、signal或retirement都不恢复旧mode。

blocking conflict使用non-exclusive interruptible `Event::listen(false, predicate)`；listener publication后predicate
短暂取得同一domain guard并只重验retired/conflict，notification从不代表grant success。unlock、conversion与
terminal cleanup都先从domain撤销grant，再在guard外drop与broadcast；terminal retirement即使没有grant也提交
recheck。`OpenedDescriptionRetirementCtx`只向VFS借出目标`File`和即时same-identity predicate；首次
`Live(1) -> Retired`后fixed cleanup exactly once运行并先于existing static hook，不暴露完整`ProcFile`、lifecycle
word、live lease、fd-table lock或callback registry。

开发者决定直接沿用现有分配器语义，故`Vec` growth保持自然实现，不增加fixed capacity、补偿状态或新errno。
source review确认domain single truth、CAS/domain-lock convergence、guard-out drop/publish、listener publication
闭环、retirement/static-hook顺序以及`FilesState`无flock policy。独立只读change-review subagent复核完整0A diff，
未修改文件、未进入0B，Apollyon/Keter/Euclid/Safe均为0；它同时确认signal分支与已取得旧lease的并发commit
只属于source-review evidence，不能记为KUnit/runtime PASS。
