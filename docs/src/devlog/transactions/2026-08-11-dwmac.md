### Gate 2 YT8511 PHY P1 implementation - 2026-08-12

**Target resolution:** 用户随后选择实现当前 DTB 中的 `rgmii` 与 `rgmii-id`，因此前一节的
`rgmii-id`-only target conflict 不再成立。实现仍只接受这两个 board-declared mode；不扩大到
`rgmii-rxid`、`rgmii-txid` 或其它 PHY/interface。

**Implementation:** 在 DWMAC1000 owner 内加入 exact-ID `0x0000010a` 的 YT8511 boot-time P1 transaction。
流程先读取 BMCR 和扩展页 `0x0c`/`0x0d`/`0x27`，执行有 deadline 的 Clause 22 soft reset，再按 Linux
6.6 Motorcomm YT8511 driver 的 read-modify-write 规则配置 delay、125 MHz clock 和 sleep PLL；随后清除
power-down/isolate、启用并重启 autonegotiation，最后取得 bounded link/BMCR/BMSR snapshot。`rgmii`
清除 RX delay 并选择 GE/FE TX-delay-disabled encoding；`rgmii-id` 同时启用 RX 与 GE/FE TX delay。

扩展页访问保存并恢复原 `PAGE_SELECT`；配置、回读或中途 MDIO 失败时也先尝试恢复页选择，再把失败交回
probe。配置后回读目标位，任何 mismatch fail closed。成功日志同时输出 BMCR reset 前后值和三个扩展页的
reset 前、reset 后、配置后三份 snapshot，使物理机能够直接验证 reset effect 和每种 RGMII mode 的最终值；
link deadline 只形成 `link=false` snapshot，因为 cable-down 是合法环境状态，不伪造 link success，也不把它
混同为 MDIO/reset timeout。

link snapshot 按 Clause 22 语义双读 BMSR，并在 BMCR restart 尚未清除或启用 autoneg 但
`BMSR_ANEGCOMPLETE` 尚未成立时强制保持 `link=false`，避免复用 reset 前的陈旧 link 位。页操作与原页恢复
同时失败时，日志分别记录 operation error 与 cleanup error；已经发生的 vendor write 采用 fail-forward，下一次
PHY reset/reprobe 是明确恢复边界。

**Validation / review:** owner-local KUnit 覆盖两种模式的 delay encoding、required clock/PLL bits、readback
mismatch 和其它 RGMII mode rejection。`just fmt kernel --check`、
`just build --preset 2k1000-la64-release`（含 KUnit、discovery/final kernel、DTB 和 raw image）及
`git diff --check` passed；既有 DTS/smoltcp/timerfd warnings unchanged。独立 review 未发现 Apollyon/Keter，

## Gate 3 in-place production attach implementation - 2026-08-15

**Authorization:** 用户授权本轮只执行 Gate 3；Gate 4、任何 semantic/contract cutover 和 current-contract 更新均未授权。

**Implementation:** DWMAC1000 的 Gate 2 `Dwmac1000Owner` 现在在同一次 platform `probe()` continuation 中被原位采用：
`Dwmac1000State` 只保存该 owner 与一次性 runtime capability，`Dwmac1000IrqContext`、IRQ private data 和 frame
provider 全部引用同一 `Arc<Dwmac1000Owner>`。Gate 3 首次且唯一调用 named `macirq` 的
`request_irq_selected(..., Some(IrqSense::LevelLow), ...)`，不重映射 MMIO、不重建最终 enhanced/extended rings 或
DMA backing，也不替换 `drv_state`。请求提交前 private data 已持有 owner；publication 仍交给现有 network registry，
attach 仍由 boot network authority 后续 drain 完成。

运行期 queue 在同一 owner 内提供 enhanced descriptor reservation：TX metadata/payload 后以 OWN-last 发布并发出
poll demand，RX 观察 OWN 清除后 acquire、剥离四字节 FCS、在 callback 锁外消费，再 refill OWN-last 并发出 RX poll
demand。IRQ handler 清 read-to-clear MAC/PCS cause，按 `CSR5_W1C_MASK` 做 device-cause W1C 与立即 readback；readback
仍有 cause 时 fail-closed quiesce。pending notification 只作为 worker wake capability，不参与 device state ownership。

行为、userspace/network ABI 或 current contracts；没有引入第二份 CSR5、pending 或 DMA backing truth。既有 common
