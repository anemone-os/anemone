### Gate 2 YT8511 PHY P1 implementation - 2026-08-12

**Target resolution:** 用户随后选择实现当前 DTB 中的 `rgmii` 与 `rgmii-id`，因此前一节的
`rgmii-id`-only target conflict 不再成立。实现仍只接受这两个 board-declared mode；不扩大到
`rgmii-rxid`、`rgmii-txid` 或其它 PHY/interface。

**Implementation:** 在 DWMAC1000 owner 内加入 exact-ID `0x0000010a` 的 YT8511 boot-time P1 transaction。
流程先读取 BMCR 和扩展页 `0x0c`/`0x0d`/`0x27`，执行有 deadline 的 Clause 22 soft reset，再按 Linux
6.6 Motorcomm YT8511 driver 的 read-modify-write 规则配置 delay、125 MHz clock 和 sleep PLL；随后清除
power-down/isolate、启用并重启 autonegotiation，最后取得 bounded link/BMCR/BMSR snapshot。`rgmii`
清除 RX delay 并选择 GE/FE TX-delay-disabled encoding；`rgmii-id` 同时启用 RX 与 GE/FE TX delay。

扩展页访问保存并恢复原 `PAGE_SELECT`；配置、回读或中途 MDIO 失败时也先尝试恢复页选择，再把失败交回
probe。配置后回读目标位，任何 mismatch fail closed。成功日志同时输出 BMCR reset 前后值和三个扩展页的
reset 前、reset 后、配置后三份 snapshot，使物理机能够直接验证 reset effect 和每种 RGMII mode 的最终值；
link deadline 只形成 `link=false` snapshot，因为 cable-down 是合法环境状态，不伪造 link success，也不把它
混同为 MDIO/reset timeout。

link snapshot 按 Clause 22 语义双读 BMSR，并在 BMCR restart 尚未清除或启用 autoneg 但
`BMSR_ANEGCOMPLETE` 尚未成立时强制保持 `link=false`，避免复用 reset 前的陈旧 link 位。页操作与原页恢复
同时失败时，日志分别记录 operation error 与 cleanup error；已经发生的 vendor write 采用 fail-forward，下一次
PHY reset/reprobe 是明确恢复边界。

**Validation / review:** owner-local KUnit 覆盖两种模式的 delay encoding、required clock/PLL bits、readback
mismatch 和其它 RGMII mode rejection。`just fmt kernel --check`、
`just build --preset 2k1000-la64-release`（含 KUnit、discovery/final kernel、DTB 和 raw image）及
`git diff --check` passed；既有 DTS/smoltcp/timerfd warnings unchanged。独立 review 未发现 Apollyon/Keter，
提出的 version byte 标注、Clause 22 link snapshot 和 page cleanup observability 三项 Euclid 已在本 slice 修正。

ISSUE-002 在两个 node 的 cold/warm/bootloader-used 实机 snapshot 取得前保持 Open。DMA32、normal descriptor、
CSR5 和 IRQ order 未运行，Gate 2 保持 **Stopped / Not Cut Over**，不进入 Gate 3。

**Stop evidence:** 独立 review 发现以下 blocking implementation feedback：

- **Apollyon / DMA lifetime：** CSR3/4 一旦发布 descriptor base，任何后续错误都必须消费 ring ownership并
  证明 TX/RX process state 已 stopped；否则普通 `DmaRegion` drop会让 allocator复用仍可能被设备访问的页，
  形成 DMA use-after-free/corruption。配置 readback、CSR5 baseline、IRQ registration和所有 timeout路径都必须
  统一走 quiesce-or-retain cleanup；单纯清 CSR6 ST/SR不足以证明 backing可以释放。
- **Keter / IRQ ownership：** 当前 IRQ core 的 `request_irq_selected()` 直接永久发布 descriptor/mapping并
  unmask source，且没有 retire/mask handle或`free_irq`。Gate 2 probe随后按 protected boundary返回

- **Keter / oracle honesty：** IRQ success必须证明预期 RI/TI cause、每次 legal W1C后无 unchanged-status repeat、
  controller pending在unmask前清除。简单累积“任意非零 enabled CSR5 cause”和handler count会把summary/stale
  cause误写成 TX/RX与IRQ-order pass；claim前 pending及随后mask/unmask日志也不证明

## R3 persistent Gate 2 IRQ ownership - 2026-08-13

**Decision / authorization:** 用户批准第二条 owner 路线并接受 R3：Gate 2 在 IRQ request 前创建每节点唯一、
长期 DWMAC1000 owner；`request_irq` commit 后由 bound platform device 保留同一 owner，Gate 3 只能原位 adopt。
Gate 2 获准按 R3 继续；Gate 3 和所有 contract cutover 仍未授权。

**Handoff and lifecycle:** owner 单一持有 MMIO、IRQ context/mapping、normal rings、DMA backing、PHY snapshot、
device state 和 characterization result。Gate 2 bounded event 后必须 mask CSR7/device interrupts、停止 MAC/DMA
并检查 CSR5 TX/RX process state。只有 quiescence 已证明才可释放 backing；无法证明时 owner/backing 保留到
后续原位 adoption、shutdown 或 terminal power-off。Gate 3 不得再次 request IRQ、重建 rings/backing 或制造
并列 MMIO/CSR5 truth。

**Reachability / continuation:** request必须先把local owner `Arc` clone到IRQ descriptor private data，再执行
commit/unmask；返回后driver立即把同一owner写入device的一次性`drv_state`，然后才开始bounded characterization。
commit期间handler由descriptor保活；commit前request失败则local owner可安全cleanup；commit后到device state/
bus bind前的IRQ也有有效handler context。commit后probe无论characterization pass/fail都返回成功完成bind，
结果由owner与结构化日志表达。Gate 3不是另一次reprobe：
Gate 3-enabled kernel在同一次probe中以private continuation原位扩展characterization-passed owner；Gate 2-only
kernel则以disabled、unpublished owner完成bind。

**Pending oracle:** `request_irq_selected()`与level flow都在内部执行unmask，DWMAC无法在调用返回后补做“unmask
之前”的证明。R3因此要求Loongson concrete irqchip在每次实际`EnableSet`前读取并输出该hwirq pending，覆盖
首次commit和handler tail；这是有Gate 2退出条件的owner-local validation trace，不增加DWMAC pending API、
不改变generic IRQ flow，也不形成第二份controller truth。若该局部observation不能闭合，触发IRQ owner stop。

**Platform probe meaning:** 因当前 IRQ core 没有 retirement，而 platform bus 只有 probe success 才绑定
driver并参加 shutdown，IRQ commit 后 `probe()` success只表示 driver接管长期资源生命周期。它不表示
characterization pass、netdev publication、Stack membership或`eth<N>` success；这些事实必须分开保存并由
结构化日志明确输出。IRQ commit前的普通失败仍须在未发布 backing或证明quiescence后返回并释放资源。

**Protected boundary / contract impact:** userspace ABI、DTB、DWMAC1000 normal-only/32-bit target、双节点
acceptance、visible network semantics、Contract Impact、current contracts和最终validation strength不变。
Gate 2不创建FrameProvider/worker/netdev；R3是accepted target owner/handoff/cleanup revision，不是current
contract cutover。

cause独立失败、legal W1C后的uncleared累计、unchanged-status immediate repeat拒绝，以及irqchip-owned
