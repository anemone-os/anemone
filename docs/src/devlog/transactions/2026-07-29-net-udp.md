## 2026-07-29 - Checkpoint 0A implementation, source audit and closure

**Implementation result:** `udp_topology`以两个不同IPv4 prefix的deterministic Ethernet interface、一份明确选择
第二interface/source的`CandidateSelection`和一个真实smoltcp UDP socket建立naive shared-engine fixture。错误的
第一interface先poll后，socket TX queue由2降为0，第一provider观察到唯一Ethernet/IPv4/UDP frame，第二provider
保持无TX；随后再poll选中的第二interface也无法恢复datagram。frame保留被选中的第二source address，但Ethernet

## 2026-07-29 - Checkpoint 0B implementation, review, validation and closure

**Implementation result:** Stack-private `UdpEndpoints`是provisional Endpoint identity/binding/admission/receive-order/
retire唯一owner。一个Endpoint为两个external interface与一个local interface分别持有private smoltcp UDP engine
resource，但engine binding只投影aggregate port，不参与conflict；Endpoint TX phase在owner queue与selected engine
之间显式移交datagram。operation-local `InterfaceId + source IPv4`在commit前验证mapping、configured source、
destination、MTU与bounded Endpoint credit；wrong-interface-first没有可消费resource，selected interface才经真实
smoltcp UDP egress形成Ethernet frame。stale/unknown interface、missing selection、unsupported source、oversize与
TX full均返回typed stack-local outcome；accepted path没有进入vendored no-source drop。

Stack-private `LocalPort`报告`Medium::Ip`，不实现或修改shared `FrameProvider`。UDP egress先进入固定packet capacity
的local-link storage，只有后续finite pump round才从同一storage进入同一Stack的normal IPv4/UDP ingress；没有
Endpoint injection、Socket-to-Socket copy、fake encoder/decoder或unbounded queue。external provider blocked时
其它Endpoint/local port仍可推进；local capacity恢复后pending engine datagram由有限后续round重试。local packet
携带的Endpoint owner只用于aggregate retire cleanup，不参与destination lookup或delivery；retire先withdraw
aggregate identity，再删除全部engine handle与pending local association，stale identity不能继续send/retire。

## 2026-07-29 - Checkpoint 0B feedback correction implementation, review, validation and closure

**Implementation result:** `UdpEndpoints::blocked_receive`、interface-wide admission gate及其retire cleanup已删除。
`drain_ingress`在aggregate queue饱和时把该Endpoint最早的engine datagram留在原engine；它不建立第二receive truth，
也不阻止同interface其它Endpoint继续normal ingress。quiescent full Endpoint不会报告software work或Immediate
recheck。TX admission在commit前以`min(interface MTU payload ceiling, Endpoint engine payload capacity)`形成唯一
maximum，capacity failure继续返回既有`Oversize { maximum }`，不会先报告send success再在pump中panic。

**Module and surface result:** ordinary Stack mapping/orchestration从`src/stack.rs`行为保持地迁入
`src/stack/mod.rs`；conditional DTO、fixture control、observation与conversion集中到同owner child module

`default-features = false`。实际source/test diff保持frozen write set，没有修改Cargo、kernel、`anemone-net-api`、

**Regression result:** `udp_topology`新增两个focused case：小engine/大MTU在pre-commit拒绝且不留下pending TX，
